# 单书 MVP 实施计划

> **For agentic workers:** 使用 superpowers:executing-plans 逐任务执行；仅在用户明确选择并行代理实施时使用 superpowers:subagent-driven-development。先阅读本计划和对应设计，不能将基础目录落地标为全书 MVP 完成。

**Goal:** 用一本真实书籍验证全书蒸馏、图谱查询和基于证据的作者知识问答。

**Architecture:** 原文只读；仓颉产物通过独立适配器转换为统一知识结构；检索和图谱由稳定接口提供给 Skill。

**Tech Stack:** Python；仓颉 v2.5.0 固定提交；JSON 知识格式。模型和检索后端在各自试验任务中通过真实评测确定。

**Spec:** [产品设计](../product-design.md)、[架构及六项影响检查](../architecture.md)。

## Global Constraints

- 原书只读；序言、推荐语和营销文字不进入作者观点蒸馏。
- 保留全正文章节覆盖；知识入库与独立方法晋级分开。
- 引用必须可在同一正文版本核对；无可靠页码时使用章节和段落位置。
- 库未就绪、接口未实现、源版本变化必须明确返回状态。
- 模型费用未知时不填估算为实际费用；不自动添加 API 凭据或付费服务。
- `configs/local.json`、真实书籍和任务缓存不进入默认交付包。

## 任务 1：单书正文与证据定位

**文件职责：** `src/distillation/` 中的正文规范化与覆盖计算；`src/knowledge/` 中的证据位置规则；`tests/` 中的真实目录抽样及合成边界测试。

**输入：** `configs/local.json` 指向的《纳瓦尔宝典》Markdown。**产出：** 带正文指纹、章节 ID、段落 ID、原位置和排除原因的规范化文档。

- [ ] 确认正文范围，逐项记录前言、序言、推荐语和附录的纳入决定。
- [ ] 先建立标题重复、段落跨界、书中引用与文件修改后旧证据失效的测试样本。
- [ ] 实现纯文本位置映射；稳定 ID 关联正文版本，禁止用会漂移的行号单独标识知识。
- [ ] 用开头、中段和结尾的真实段落验证可回读；记录覆盖和排除数量。

## 任务 2：章节蒸馏与全书整合

**文件职责：** `src/distillation/` 中的仓颉适配与任务状态；`prompts/distillation/` 中的三阶段补充提示词。

**输入：** 任务 1 的完整正文及章节目录。**产出：** 候选卡片、方法卡片、章节覆盖表、全书档案与逐任务运行记录。

- [ ] 先用一个章节比较仓颉原始输出与补充规则输出，检查支持原文、边界、一般知识保留情况。
- [ ] 明确本轮模型执行方式及可观察的用量字段；尚无调用接口时由当前 Agent 按提示词执行并记录，不能宣称脚本自动蒸馏。
- [ ] 实现以正文指纹、提示词版本和模型配置标识任务的断点缓存；失败单元独立重试。
- [ ] 完成全部纳入章节，整合重复概念，保留条件差异和无法确定的归属。
- [ ] 每张卡片必须通过证据定位与人工抽样核验；失败产物不进入已验收书库。

## 任务 3：入库、图谱与检索

**文件职责：** `src/knowledge/` 中的卡片和关系验证；`src/retrieval/` 中的检索与关系展开；`src/interfaces/` 中的工具入口。

**输入：** 已验收知识与证据。**产出：** 可重建索引、关系数据，以及架构文档定义的五项查询能力。

- [ ] 先测试悬空关系、跨书 ID 冲突、关系方向、未知证据和旧正文版本引用。
- [ ] 实现知识版本验收及切换；发布失败保留上一可读版本。
- [ ] 比较关键词基线与语义/混合检索，使用同一组真实问题记录召回证据及延迟。
- [ ] 让关系查询实际补充前提、反例或组合方法；只输出脑图图片不算通过。
- [ ] 验证书籍/作者过滤、空结果、库未就绪、中文问法和出处回读。

## 任务 4：作者 Skill 与单书问答验收

**文件职责：** `skills/second-brain/`；`tests/acceptance-questions.md`；问答运行记录保存在 `data/jobs/`。

**输入：** 任务 3 的可用查询接口。**产出：** 一位作者的一本书知识问答闭环，明确书籍覆盖边界。

- [ ] 将 Skill 文件读取路径切换/扩展到已实现工具；核对实际命令，不保留虚构调用示例。
- [ ] 使用验收题集测试事实查找、应用、跨章节综合、范围不足和错误引语。
- [ ] 每条回答核对引用位置、观点归属、建议与原文的区分；与普通回答及仓颉基线并排评价。
- [ ] 使用未参与提示词调整的新问题复测，记录不足，不能只展示最好的案例。

## 任务 5：交付与批量工作流固化

**输入：** 单书已验证的工具、Skill、数据格式。**产出：** 可迁移的本地交付包和可续跑的蒸馏流程。

- [ ] 通过显式白名单构建交付内容；验证没有原书、本机路径、凭据、缓存或嵌套 `.git`。
- [ ] 在独立临时用户数据目录验证安装、查询、升级和私有书库保留。
- [ ] 将已验证的提示词与阶段脚本固定版本；批量队列只做参数化组合，不另造一套蒸馏逻辑。
- [ ] 第二位作者加入后，另验多作者分歧、过滤与综合；不提前宣称专家团验证完成。

## 启动与完成条件

本轮仅执行基础阶段。后续单书实施按任务顺序执行；书籍默认建议为《纳瓦尔宝典》，用户可更换。每个任务开始前细化其函数签名和对应测试，完成后记录实际结果。此文件是分阶段实施路线，不伪装为已执行记录。


## 2026-09-05 执行更新

已按 [本轮执行记录](2026-09-05-mvp-execution.md) 跑通单书闭环，结果见 [验收报告](../mvp-verification.md)。上面的原始任务清单保留为设计基线，不以一键全勾代表所有探索已执行。

实施调整：没有先单独做一章的两种蒸馏对照，而是在全文完成后比较仓颉原入口与项目知识入口的实际回答；抽样为 Agent 回读，没有人工逐卡审计；固定复测 10 题、真实 Skill 行为 4 题，原建议题集未全量运行。自动模型批量、失败调度、多书合并和第二位作者仍留在后续阶段。
