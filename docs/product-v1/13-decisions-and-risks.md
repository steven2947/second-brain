# 决策、风险与待确认事项

状态：产品设计默认值。不是所有默认值都获得了真实用户/生产环境验证；不把“可以先这样设计”写成已完成采购、授权或上线批准。

## 重要选择与取舍

| 决策 | 本版选择与原因 | 代价/替代方案 | 改变它的触发条件 |
| --- | --- | --- | --- |
| 核心复用 | Python调用核心保留，Web只做认证、持久化、任务、适配和呈现 | 比复制一份JS逻辑多一层接口，但避免语义漂移 | 原核心确实无法满足隔离/性能时先提交同题回归方案 |
| 技术架构 | React/Vite + Django + PostgreSQL的模块化单体 | 两种语言需维护；全栈单语言能少一套环境却要重接Python | 团队主要技能/部署环境改变后重新比较，不因模板流行随意换栈 |
| 数据库 | 开源PostgreSQL，自托管开发，不先买数据库 | 备份维护由部署者负责；托管可减运维但有成本 | 实际运维成本超过托管收益，取得预算授权 |
| 任务队列 | PostgreSQL队列+独立worker进程 | 多承担lease/幂等实现，不适合一开始就承诺极大吞吐 | 真实负载显示DB争用或复杂调度成为瓶颈 |
| 授权单位 | 一个问题固定一个同权限release，可跨该release内多书 | 首版不支持跨任意不同权限release联合检索 | 有真实使用需求再设计联邦检索及证据ID命名空间 |
| 知识与提示词 | 知识卡为资产、调用规则为服务端编排，不为每张卡生成一个Skill | 少了随意把单卡安装成Skill的便捷 | 将来有独立插件产品时再做受控导出，不改变主库真源 |
| 答案展示 | 先充分建议，再按需原理/证据/质询；提供学习与续聊入口 | 不如只显示简答省空间，需要良好信息层级 | 用户测试证明默认展开量过高时调折叠，不删原理内容 |
| 流式体验 | 真实阶段进度+验证后结果，不裸流内部草稿 | 用户需要等待成品，需要明确状态和取消 | 只有可证明不漏未采用/受限内容的分段验证才启用更早流出 |
| 首版首页 | 现代图书馆+原创3D馆员，移动/低性能静态替代 | 增加模型制作、性能和许可工作 | 用户看首版后换形象；保留可编辑源，不重做业务 |
| 开放模式 | 邀请注册、获准知识、无支付/公开分享 | 不是立即面向所有人规模获客 | 邮件/合规/预算/安全与运营准备通过后开放 |
| 可编辑性 | token、文案、组件、人物配置解耦 | 不是无代码任意拖拽编辑器 | 后续验证Onlook等兼容性后可选接入 |

以上是本方案的设计判断，不声称竞争产品都按此架构实现。

## 变更记录模板

编号/日期；原决策；新决策；用户证据或测量；影响REQ、WP、AT；字段/API迁移；旧档案兼容；同题回归；许可/成本影响；批准人。规则或现有文档采用局部补丁，未点名内容保留。

本版不新增“必须全库都调用”“必须每题五轮”“必须四位名人”“必须很多卡”等机械指标；这些会降低可信度和用户便捷性。原理可以充分解释，证据归属与权限不能自由发挥。
