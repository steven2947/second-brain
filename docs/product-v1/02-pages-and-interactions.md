## 信息架构

```text
/                         图书馆首页、公开自编示例
/login                    登录
/register                 邀请注册
/forgot-password          找回入口
/reset-password           单次重置链接落点
/app                      我的工作台
/app/problems/new         新问题
/app/problems/:id         问题讨论与历次分析
/app/library              获准书房
/app/library/:release/books/:book  书籍详情
/app/library/:release/cards/:card  知识详情
/app/saved                收藏
/app/learn                学习记录
/app/learn/:id            方法学习与练习
/app/actions              行动记录
/app/settings             资料、主题、用量、数据管理
/app/trash                回收站
/admin                    独立管理入口
/privacy /terms           经负责人确认的政策页面
```

`/app/*`校验登录；资源路由继续校验归属。未知/无权对象统一展示“不存在或当前不可访问”，不暴露书名或用户信息。登录成功仅返回同站合法路径，拒绝外部跳转地址。启用MFA的管理员在密码后进入验证码步骤，challenge阶段不显示已登录；过期回到登录而非绕过验证。

## 各页结构与行为

| 页面 | 主要区域 | 动作与结果 | 空/错/恢复 |
| --- | --- | --- | --- |
| 首页 | 品牌、简短价值、3D馆员、示例预览 | 开始使用→未登录去登录、已登录去工作台；示例展开知识与质询 | 3D失败保留静态封面和全部入口；示例显式标自编且不连接私有数据 |
| 登录 | 邮箱、密码、显示密码、找回、注册入口 | 成功轮换会话并进入工作台；提交时只禁用提交按钮 | 错误统一“不匹配或账号不可用”；保留邮箱，不在刷新后保存密码；限流提示剩余等待 |
| 注册 | 邀请、昵称、邮箱、密码、政策确认 | 仅有效邀请可创建；无SMTP的本地模式用管理员邀请开户，不伪造邮箱已验证 | 邀请过期/已使用统一说明；网络失败不得重复创建账户 |
| 找回/重置 | 邮箱或单次重置令牌、新密码 | 统一响应避免枚举；实际发送结果与界面措辞一致 | 无邮件服务时明确该渠道不可用；不把重置令牌写浏览器持久存储或分析日志 |
| 工作台 | 新建入口、最近问题、待行动、继续学习 | 搜索自己问题；改名、归档、进入历史、进入新问题 | 新用户引导创建或看示例；历史加载失败可重试，不显示空库冒充成功 |
| 新问题 | 自然语言输入、任务目标、知识集选择 | 选择一个获准知识版本创建档案；用户不需要选全部书或填JSON | 无知识/模型时解释配置缺口；仍可保存问题，不自动发送模型请求 |
| 分析室 | 导航、对话主区、知识侧栏、底部输入区 | 追问、立即分析、不知道、取消；点书目开侧栏；切换运行版本 | 刷新恢复当前任务；新事实先入档再分析；无权时旧内容立即停止加载 |
| 书房/书籍 | 搜索、作者/类型筛选、封面、章节与卡片 | 列表/书架切换；卡片详情；收藏；“用它分析”附可见上下文 | 缺作者显示“作者信息待核实”，不猜；无封面使用设计好的文字封面 |
| 知识详情 | 来源、主张、原理、条件、关联、短引 | 打开证据、进入学习、选择该知识发起问题；面包屑返回 | 原卡浏览标“整理内容，未针对当前问题采用”；无证据说明缺口 |
| 学习 | 学习目标、当前主题、讲解、练习、反馈 | 从答案选方法；AI解释；提交练习；查看反馈并继续 | 没答题不标掌握；反馈生成失败保存用户原回答，允许重试 |
| 行动 | 按问题分组的行动、状态、观察记录 | 标进行/完成/放弃，补充结果；“据此继续分析”需确认发送 | 完成状态不等于建议有效；旧建议保持原文，新反馈另存 |
| 设置 | 资料、主题、使用情况、会话与数据 | 修改昵称、改密、退出所有会话、导出、删除账号 | 导出显示任务状态；删除要求再次认证和明确确认；不暴露后台模型密钥 |
| 管理端 | 用户、授权、知识版本、任务、配额 | 禁用账号、授权/撤销知识集、暂停服务、处理任务 | 高风险动作显示对象与影响；不默认提供私有对话全文查看入口 |

## 分析室的渐进展开

桌面≥1280px：导航约220px，主阅读区弹性（正文约68个汉字宽内），来源侧栏约360px且可收起。1024–1279px导航收窄、来源覆盖式抽屉；<768px单列，来源/版本/筛选为独立抽屉，输入区尊重安全区。不可同时弹出多个全屏抽屉。

正式答案分三层，但不是三页：

1. 建议先交付，讲清优先、做法、取舍、前提，来源用简短按钮就近可点。
2. 按知识组展开“《书名》｜作者｜知识名称”，保留充分原理、边界、事实映射；折叠仅节省显示空间，不删除证据。
3. 关键交锋展示原主张、被质疑前提、现有证据和裁决影响；旁列未决项、行动、改判条件与来源账本。

最终内容底部有可操作的继续路径，最后一行保留“继续和 AI 聊：……”；点选填入输入框，用户发送后才消耗模型调用。来源、说明放在该行之前。系统/政策页脚属于页面外壳，不插入答案正文末尾。

不可把所有原理默认缩成一句，也不可强制每个答案出现同样数量的卡片或戏剧对话。系统延伸用标签与正文表述双重区分。

## 核心状态机

问题业务状态：`active → archived → active`；任意未删除问题可进入`deleted`，保留期内恢复。它与澄清开关、任务状态分别存储，不用一个status混装。

交互状态：`idle → processing → awaiting_user`（得到追问），或`processing → showing_answer`（得到答案），或`processing → error/cancelled`。用户回应才进入下一轮；网络重连重放同一提问，不增加轮数。

任务状态：`queued → running → succeeded/failed/cancelled`；运行中取消先到`cancel_requested`，直到后台确认才显示已取消。重试创建新任务并关联原任务，不把原失败覆盖为成功。详情见06、07。

## 必须覆盖的边界交互

- 中文输入法组合期间Enter不发送；普通Enter发送、Shift+Enter换行，按钮始终可用。
- 双击发送只创建一次任务；刷新/重连不能重复扣用量或再问一次。
- 用户向上读历史时不强制滚到底；新内容到来显示“有新内容”。
- 两个标签页同时发消息：其中一个成功，另一个显示修订冲突，保留未发草稿并重新加载，不静默覆盖。
- 正在分析时用户更正事实：允许保存消息并取消/作废旧运行，旧结果不得冒充基于最新事实。
- 选“直接分析”或“不知道”结束主动背景问诊；不把第六轮藏在继续路径里。
- 删除/退出/撤权后，清空内存中的个人查询缓存，不在localStorage留聊天；浏览器后退必须重鉴权。
- 断网保留当前页面内的未提交草稿；首版不持久化敏感草稿到本地磁盘，不承诺离线编辑同步。
- 新知识版本发布后，旧问题仍用固定版本；首版不提供原问题一键换库。需要另一个release时新建问题并由用户确认带入的背景，不自动迁移旧来源或答案。撤权优先于历史回看。
- 没有知识证据时呈现覆盖缺口；一般建议分开标识，不展示假引用。

## 验收材料

每条主路径要有屏幕录制或浏览器检查记录，覆盖桌面、390px手机、明暗模式、键盘和慢网。交互录像只能证明被操作到的状态，不代表权限或分析语义已验收。
