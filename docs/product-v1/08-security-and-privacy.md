# 安全、权限与隐私设计

状态：设计要求，不是安全认证或法律意见。上线地区、运营主体和知识许可范围尚未确认；正式隐私政策、用户协议及内容授权须在公开运营前完成审核。本文件定义工程控制，不宣称“蒸馏后自动无版权风险”。

## 威胁边界

需要保护的资产：账户凭证、个人问题与反馈、受限知识、内部提示词、模型密钥、导出文件和备份。外部输入包括用户消息、蒸馏原文、模型输出、浏览器参数以及管理员导入包；均不能充当授权指令。

| 风险 | 必须具备的控制 | 验收证据 |
| --- | --- | --- |
| 修改UUID读取别人记录 | 服务层owner过滤、父子归属约束、个人表RLS | 双账号正反测试覆盖读写/搜索/分页/任务/导出 |
| 检索时混入未授权书库 | 检索前选定获准release；索引按release隔离 | 不可见书籍的标题、命中数、引用均不返回 |
| 已撤权但旧答案仍暴露 | 每次读取、事件发送、发布、下载再鉴权；失权清理前端内存 | 撤权前后同对象与断线重连对照 |
| 提示词注入与套取 | 模型无权限修改接口；上下文分隔；输出白名单；有限工具 | 恶意卡片/用户输入不会增加grant或返回内部上下文 |
| 富文本脚本与路径穿越 | Markdown禁原始HTML或严格净化；URL协议白名单；服务端路径映射 | 脚本、javascript链接、编码路径绕过测试 |
| 偷用模型/重复计费 | 服务端预算预约、限流、幂等、并发上限 | 重复提交仅创建一次业务运行，预算并发不超限 |
| 队列重跑发布旧答案 | lease/fencing、输入revision、取消位和grant一起校验 | worker重启/超时/晚到响应不能覆盖新答案 |
| 管理误操作 | 最小权限、再次认证、审计、发布/撤销确认 | 普通staff无权读聊天正文或改超级管理员 |
| 备份/日志泄密 | 非公开路径、备份加密、日志白名单和保留期 | 扫描无密码/token/原始提示词/聊天全文 |

## 权限矩阵

“本人”并不自动意味着“有权看其中的知识”：包含知识内容的对象还要检查有效grant、release未撤销。

| 资源/动作 | 访客 | 普通用户 | 知识管理员 | 系统管理员 |
| --- | --- | --- | --- | --- |
| 首页自编演示、协议 | 可读 | 可读 | 可读 | 可读 |
| 问题、消息、学习、行动 | 不可 | 本人 | 仍仅本人 | 默认仍仅本人 |
| 获准书房、来源片段 | 不可 | 有效grant | 自己获准才可读 | 不以后台身份自动转给普通API |
| 导入/审核/发布知识版本 | 不可 | 不可 | 指定操作权限 | 指定操作权限 |
| 给用户授权、撤销授权 | 不可 | 不可 | 显式grant管理权限 | 可按流程操作 |
| 禁用账号、调配额 | 不可 | 不可 | 不可 | 可操作并审计 |
| 提示词/密钥 | 不可 | 不可 | 不可 | 服务器运维权限另行控制，不提供网页下载 |
| 个人导出/删除 | 不可 | 本人再次认证 | 不可代替本人发起 | 经核验支持流程；不可静默代导出 |

不得把“is_staff=true”理解为无限管理员。业务角色用显式权限组；数据库超级用户和生产shell属于单独运维边界。首次真实用户测试前，管理入口限制访问网络并强制管理员多因素认证，恢复码离线保管；未完成时只允许本机演示，不公开管理入口。

## 租户隔离实施要求

1. 用户身份只来自验证后的会话；请求里的owner相关字段不接收。
2. 每个个人对象以owner+id查询；跨父子对象使用复合归属约束。导出、异步任务同样适用，不只聊天API。
3. PostgreSQL个人表启用RLS；应用运行账号不是表owner、superuser或BYPASSRLS。迁移账号分离，运行时不能自行切换高权角色。
4. 事务开始用事务局部tenant上下文，缺失时拒绝；连接回收后不得残留上一个用户。集成测试用实际运行角色，不用测试超级用户制造假通过。
5. Worker只从受控任务记录获得owner；再检查账号状态、auth/access revision、对象权限。管理员导入走独立最小权限路径，不能复用“任意租户模式”。
6. 共享知识表不能套用个人owner假模型。只允许后端通过有效grant读取；release是首版最小授权单元。单release内不能夹杂不同用户权限的书。
7. 缓存键至少包含owner、access_revision、release fingerprint及查询/输入版本；授权不可只依赖缓存。SSE每次输出检查，长连接发现撤权立即终止。

RLS是额外防线，不替代服务权限；数据库所有者等角色可能绕过策略，必须验证实际运行角色。[PostgreSQL RLS官方说明](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

## 提示词与模型安全

提示词、模型密钥、原始上下文只在服务端运行环境；不得放在前端环境变量、静态资源、Source Map、浏览器日志或公开API。公开DTO逐字段选择，不对内部字典“删几个敏感键再返回”。

这能阻止用户直接下载服务端提示词，但不能保证模型绝不透露提示词相关信息。权限、预算和数据保护必须由确定性程序执行，不能依赖一句“不要泄露”。[OWASP提示词泄露风险](https://genai.owasp.org/llmrisk/llm072025-system-prompt-leakage/)

首版模型不具备执行shell、发邮件、改权限、付款或任意URL抓取工具。用户提到文件/网址不自动访问。模型供应商地址由部署者受控配置，普通用户不能输入URL令服务端代为请求。

默认模型请求只发送当前必要的用户背景及获准选定知识；传输范围在使用前说明。不能承诺第三方“不保存/不训练”，必须按实际供应商条款和配置核验。模型未配置时诚实显示不可用。

## 账户与网页防护

- Django密码哈希/会话机制；强口令校验、登录/找回限流、统一账号错误；密码或权限重大变化使旧会话失效。
- 同源Cookie，生产Secure、HttpOnly、SameSite=Lax；CSRF与Origin校验。HTTPS、CSP、frame限制、referrer策略按生产配置测试。
- 不把聊天保存在localStorage，不缓存私有API到Service Worker。退出/换账号清理前端内存和查询缓存，旧浏览器返回按钮不能显示前用户正文。
- Markdown链接打开外部网页明确标识，不自动请求远程图片追踪用户；默认不显示第三方远程图片。上传/导入压缩包限制大小、展开总量、路径和文件类型。
- 引用原文不是安全字符串。前端统一净化渲染，3D资源也是受许可和体积限制的静态文件。

## 数据生命周期（首版默认策略，需展示给用户）

| 数据 | 默认保留与处理 |
| --- | --- |
| 正常账户的个人内容 | 持续保存，用户可导出、归档、删除；不默认作为全局训练资料 |
| 问题回收站 | 删除后普通列表和分析不可访问，30天内可恢复；到期24小时内清理在线数据 |
| 账户删除 | 立即禁用会话并停止任务，7天核验冷静期；到期24小时内清理在线个人数据；期内取消需支持流程核验 |
| 导出文件 | 完成后24小时有效，仍需登录和实时权限；到期清理 |
| SSE历史事件 | 7天；不留原始模型流，过期通过状态API恢复 |
| 日志、用量、操作审计 | 常规90天；账户删除时移除正文关联和可直接识别信息，仅保留必要安全/计量摘要及清理结果 |
| 幂等记录 | 至少24小时，默认48小时；清理前不允许重建相同业务提交 |
| 模型内部草稿与请求快照 | 加密/受控存储，排障默认不读正文；运行终态7天后清理，仅保留可验证成品与版本元数据 |
| 加密备份 | 滚动35天；账户删除不即时改写历史备份，但恢复后必须重新执行删除清单，不能复活账号 |

删除请求、撤权记录及备份恢复用的清理清单不得随同最早一份备份提前消失；保留到最后可能含旧数据的备份过期再加7天。法定留存要求若适用，应由运营审核后明确调整政策，不能由开发者默默无限期保存。

撤销知识授权只能阻止后续获取，不能远程收回用户已下载或截图的材料。PRD中的撤权能力指服务端、受控下载与应用内缓存的后续访问，不能作不可撤销传播的虚假承诺。

## 版权与发布控制

本机拥有文件不等于可商业提供原书或卡片。每个release发布前记录来源、权利依据、允许对象/用途、引用约束、到期时间和审核人；未审通过不得公开。演示优先用自编材料、确认可用的开放许可或公版材料，译本及插图单独核验。

引用长度约束是内部内容控制，不是法定安全线；改写、署名、通过相似度检查都不自动取得授权。先保留学习和分析的可追溯来源，再按授权决定可展示的范围。3D、字体、图标、封面与依赖同样建立许可清单。

设置内容纠错/权利联系入口；收到问题可先暂停相关release并清缓存、阻止新运行，再核实。上线前按实际地区和业务进行法律审核；此工程文档不替代该审核。

## 安全验收产物

威胁模型、权限矩阵测试、依赖/密钥扫描、提示词暴露检查、备份恢复记录、管理员权限证据。采用ASVS检查清单组织证据，但完成内部检查不等于取得认证。[OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/)
