# 本地管理员入口

个人导出、回收站、到期清理及核验后取消注销见[隐私维护说明](privacy-operations.md)。高权限维护只在可信本机命令执行，不把迁移凭据交给网页 API 或普通 worker。

当前实现独立管理登录、第二因素、恢复码、重新验证和显式权限展示；知识导入、权利审核、发布和授权页面及后端已接入，开发库生效/验收状态见[施工进度](product-v1/PROGRESS.md)。看到某项权限不代表所有运营模块已经上线。普通账号入口保持不变。

## 初始化（由部署负责人在本机执行）

先完成本项目数据库迁移，并在安全终端载入本项目环境。API/worker只使用运行数据库凭据；以下命令才使用独立迁移配置。不要把密码、验证码、环境秘密粘到聊天或命令参数中。

在项目根目录的真实交互终端运行，`--output`替换为已配置`SB_PRIVATE_DATA_ROOT`下尚不存在的文件绝对路径：

```bash
.venv-product/bin/python server/manage.py bootstrap_admin \
  --settings=config.settings.migrate \
  --output /本项目私有目录/admin-enrollment.json
```

命令交互询问新管理员邮箱、显示名、角色和两次密码，不允许把已有普通账号直接提升为管理员。角色为`system-admin`或`knowledge-admin`；前者配置全部明确管理权限，后者仅配置知识管理权限。账号并非超级用户。

初始化文件权限为0600，包含认证器导入URI、手动密钥及一次性恢复码；它是秘密，不是日志。只在本机使用并妥善保管，禁止提交Git、分享截图或放到Web公共目录。用认证器导入后，在命令内输入当前六位验证码，验证成功才启用设备和角色。

若已生成文件但验证未成功，不要反复新建账号，可继续：

```bash
.venv-product/bin/python server/manage.py confirm_admin_mfa \
  --settings=config.settings.migrate
```

命令要求真实TTY且拒绝覆盖已有秘密文件。本项目当前没有自动创建任何真实管理员；测试账号仅存在于独立测试数据库。

## 页面使用

- 开发入口：`http://127.0.0.1:5173/admin/login`，不放在普通用户公共导航。
- 使用密码和认证器验证码登录；遗失认证器时可显式切换单次恢复码。失败后密码和令牌清空，不自动重复提交。
- `/admin`只显示当前身份、服务端实际授予的权限与验证时效，不读取用户聊天。权限撤销不等到重新登录才检查。
- 会话最长8小时；高风险操作要求最近5分钟内完成密码与第二因素重新验证。管理会话不能代替普通用户会话调用个人接口。
- 离开/隐藏页面清理管理内容与凭据，返回时重新读取当前身份；退出成功后返回管理登录。

## 数据与维护边界

TOTP使用`django-otp==1.7.3`的成熟验证组件（Unlicense）；秘密通过`cryptography==50.0.1`的Fernet加密（Apache-2.0或BSD-3-Clause），恢复码仅存哈希与消费时间。版本/许可参考[django-otp](https://pypi.org/project/django-otp/1.7.3/)和[cryptography](https://pypi.org/project/cryptography/50.0.1/)。只安装到本项目`.venv-product`，未修改原蒸馏环境。

加密子密钥由本项目`SECRET_KEY`通过独立用途的HKDF派生。备份数据库时必须同时安全备份该密钥；直接更换它会使旧TOTP密文无法解密。正式轮换需维护窗口重新封装密文或重新登记第二因素，当前没有自动轮换工具，不能简单改环境变量当迁移完成。

数据库运行角色不能创建/修改角色授权、登记设备或改写历史审计；设备计数与恢复码消费在身份范围内处理。审计只记录管理动作、账号ID、请求ID和时间，不记录密码、验证码或用户问题。后续管理动作必须复用这套权限检查，不能在API进程注入迁移账号绕过限制。

真实SMTP找回密码、管理员设备自助轮换和部署演练仍属于后续工作，不因管理登录完成而标记整套产品完成。账号运营入口说明见下文；当前迁移和验收结果以施工进度为准。

## 知识进入产品的实际流程

1. 部署负责人准备已经蒸馏/编译好的**固定知识版本目录**，置于正式配置的`SB_LIBRARY_ROOT`内；不是直接上传PDF，也不接受`CURRENT`指针、任意URL或符号链接。原书只读，产品不负责重蒸馏。
2. 在持有本项目迁移配置的本机终端登记。`storage-key`为该根内目录的相对键，`staging-key`为供网页选择的唯一标识。登记会实际验证目录和完整指纹，但不导入数据库、不批准权利、不发布：

```bash
.venv-product/bin/python server/manage.py register_knowledge_source \
  --settings=config.settings.migrate \
  --staging-key my-collection-v1 \
  --storage-key releases/my-collection-v1 \
  --title '我的固定知识版本' \
  --description '说明这一版本的书籍范围'
```

以上为部署操作示例，不代表已替你登记真实书籍。当前开发配置的知识根仍为项目`examples`，没有改动或写入该目录；真正接入本地书库时应显式配置合适的私有知识根，不为赶进度覆盖原样例。

3. 登录`/admin/knowledge`，从已登记来源选择“开始技术导入”。常驻`runworker`处理真实持久任务；刷新页面可读取本账号导入记录。技术成功状态仍为“待权利审核”，失败不生成已发布版本。
4. 打开版本，核对书名、作者和数量。逐份填写权利依据、适用书籍、期限和用途；浏览、分析/学习、原文短引分开选。授权/许可证等依据需要私有目录中实际存在的证明文件键。证明正文与本机路径不通过API返回。
5. 明确选择每条记录的批准或拒绝，并确认提交完整审核记录集。既有批准记录保留为失效历史，新记录由服务端绑定审核人和时间。审核必须覆盖全部书的浏览用途才能成为可发布版本；仅浏览许可不自动允许分析或短引。
6. 权利通过后单独确认“发布知识版本”。发布时重新验证文件指纹与当前权利，不凭页面状态跳过检查，也不会自动为所有用户授权。
7. 具备`grants.manage`的管理员，在版本下填写目标普通账号ID，核对并授予有期限或无期限授权。具备`accounts.view`时可主动查找账号，不读取聊天。需要撤权时填写原因并明确提交。
8. 权利条件变化时撤销发布，停止后续访问。已发布记录不能直接改写权利，先撤销再审核；撤销不删除原书、历史版本或用户原始问题。

重要操作均需最近5分钟的双因素验证；可在知识页右侧重新验证后继续，不自动提交之前失败的写请求。网络结果不明时先刷新记录；同内容在当前页面手动重试沿用幂等键。网页隐藏/退出后清理私有页面和未提交草稿。

当前导入有界处理限制为每个登记版本最多100MiB、10000个文件/目录节点；超限不会悄悄截断导入，需明确评估批次或容量策略。该限制不是“整库任意规模已验收”的声明。后续部署前应针对实际完整知识版本做容量验收。

## 账号与运营工作台

入口为`/admin/operations`。只有对应明确权限才显示操作区；知道网址不能绕过后端鉴权。下面是使用说明，不代表已替真实用户执行操作。

| 权限 | 页面能力 | 边界 |
| --- | --- | --- |
| accounts.view | 主动查询普通账号摘要 | 不读取密码、聊天或权限秘密 |
| accounts.disable | 停用、恢复指定普通账号 | 不修改管理员或待删除账号；恢复不会复活旧会话或追加知识授权 |
| quota.manage | 读取、调整当前UTC月次数上限 | 带原月份及修订号，不能低于已结算与预留总数；不是金额预算 |
| accounts.invite | 生成本机捕获邀请 | 仅开发捕获交付，不冒充SMTP发送 |
| operations.view | 当前UTC月任务状态计数 | 实际任务聚合，不含用户问题、租约秘密或模型内容 |
| feedback.review | 全部历史反馈分类计数 | 不是某月趋势，不读取用户评论正文 |

账号列表需要主动点击“查询普通账号”。只有额度或停用权限时也可手动填入明确的普通账号UUID，不额外获得整个账号目录。停用/恢复必须核对目标、填写原因并确认；若当前状态已变化，刷新列表重新选择，不盲目重试。

修改额度前点击“读取本月额度”。页面显示已结算、执行中预留及总上限；保存同时发送`expected_revision`与`expected_period`。其他任务结算或跨UTC月份会使旧值失效，需重读后再操作。缺少消费记录的默认额度是服务端配置投影，单纯读取不会建桶。金额、真实模型token费用仍不可用时不按0元展示。

邀请成功只显示`delivery_id`和到期时间。部署负责人在`SB_PRIVATE_DATA_ROOT`中按`invitation-{delivery_id}.json`取件，文件为0600，含对应邮箱、邀请令牌和有效期；通过合适的私密渠道交给对应收件人，在`/register`手工填写令牌。不要把令牌拼进网址、公开日志、截图或Git，也不要把投递编号当成邀请令牌。当前没有向邮箱发送邮件，生产环境未配置真实交付时会明确拒绝，不能把本机捕获模式直接当生产邮件服务。

重要写操作复用最近5分钟双因素验证、CSRF与幂等。网络结果不明时，同页面同内容的手动重试沿用提交编号，不自动补交；失效身份或页面隐藏会清理当前账号与表单。此批不自动建立真实账号，不替你发出真实邀请。
