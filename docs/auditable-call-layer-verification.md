# 可审计知识调用层验收记录

验收日期：2026-09-06

## 验收对象

- 真实知识库：Second Brain MVP seed library
- 知识版本：`138e911ba4d4581b71d1c09c`
- 内容规模：1 本书、109 张知识卡、776 条证据、79 条关系
- 测试问题：我每天都在接零散工作，怎样积累长期价值？
- 调用模式：standard

## 实际结果

- `analyze`：混合检索召回 30 张候选卡；首次下载免费嵌入模型约 16.53 秒，缓存后约 1.25 秒。
- Agent 分析草稿：逐一处理全部 30 张候选，采用 6 张、淘汰 24 张。
- `validate-analysis`：生成 6 张见证卡、4 个行动步骤及 45 条证据定位，耗时约 0.68 秒。
- 每张采用卡均包含来源、原理、情境映射、判断作用、条件或边界。
- 交叉验证覆盖共识、冲突、限制、替代方案和证据缺口。
- 每项行动均包含完成标准、验证信号和停止条件。
- 命令行过程不调用付费模型，CLI token 消耗为 0；Agent 对分析草稿的 token 消耗当前运行环境不可观测，记为 unknown。

## 降级与限制

系统 Python 缺少 `fastembed` 时，调用层能自动降级为关键词检索，并明确记录 `retrieval_degraded=true` 与原因。随后按锁文件建立 Python 3.12 隔离环境，并补入当前 SOCKS 网络环境需要的 `socksio==1.0.0`，真实混合检索成功，记录为 `mode=hybrid`、`retrieval_degraded=false`。

关键词降级版与混合版前 30 张候选重合 25 张、前 10 张重合 6 张。混合检索将“以产出而非忙碌时长衡量知识工作”从第 3 位提升到第 1 位，并召回更贴近个体起步条件的“用代码和媒体降低获得杠杆的门槛”。

本次真实知识库只有《纳瓦尔宝典》一本书，因此只能验证同书内部的支持、挑战与边界，不能声称已经完成跨作者共识。随着其他书籍进入同一知识库，现有策略会优先保留跨书候选，但仍由 Agent 判断其是否真正相关。
