# 十本新增书籍蒸馏与多书知识库设计

## 背景与目标

当前真实知识库只包含《纳瓦尔宝典》一本书。原书盘点工具确认本机配置指向的书库共有 168 本 Markdown 原书；现有系统已经支持单书 `prepare → assemble → validate → publish` 闭环，也支持本地 v1.2 Markdown 成果一次导入多本书，但原生蒸馏产物仍按单书装配，`publish` 切换的是完整快照而不是追加书籍。

本设计为下一阶段选定 10 本新增书籍，建立可恢复、可审计的逐书蒸馏批次，并在全部逐书验收后生成包含原有《纳瓦尔宝典》与新增书籍的多书候选知识库。目标不是把书名写入目录，而是为每本真实原书留下范围、正文指纹、蒸馏任务、证据、语义复核和合并验证证据。

本阶段不启用 OpenSpec，不修改原书，不自动调用付费模型，不上传原书或发布到外部服务。

## 方案比较与决策

### 方案 A：十本同时蒸馏并最后一次性验收

优点是启动快、较早形成宽知识面；缺点是任何一本的范围错误、证据错误或模型输出缺陷都会在最后阶段集中暴露，失败定位和返工成本最高。放弃。

### 方案 B：5+5 两波次，逐书验收后合并

第一波先覆盖知识管理、批判性思维、学习、创业和营销，使用五种不同主题校准范围规则、卡片质量和关系装配；第二波处理篇幅更长或跨领域关系更复杂的书。每本书都有独立候选目录，只有通过单书门禁后才能进入合并候选。采用此方案。

### 方案 C：逐本蒸馏并立即发布到主库

每本完成后即可使用，但会把尚未经过多书冲突、检索和跨书 ID 检查的中间状态暴露给当前用户，且会频繁切换 `CURRENT`。不采用。逐书候选可以独立生成，但正式发布仍以完整多书快照为单位。

## 目标数据流

```text
只读原书
  -> 十书计划清单与逐书 scope
  -> prepare（正文指纹、标题范围、段落 ID、任务状态）
  -> Agent 按分组完整阅读与蒸馏
  -> 每本书独立 assemble / complete / validate
  -> 十本候选合并器（保留每本书的来源与 ID）
  -> 多书 validate + 检索复测 + 语义抽样
  -> 显式批准后 publish 到新快照
```

原书和已发布 `CURRENT` 在整个蒸馏期间保持不变。十本新增书籍全部通过门禁后，最终主库预期包含 11 本书（原有《纳瓦尔宝典》加本批新增 10 本）；任何一本未通过时，不得把“十本版本”宣称为完成。

## 逐书范围与事实源规则

1. 计划清单只保存书名、稳定 `book_id`、相对原书路径、领域、波次和状态；不保存绝对路径、模型凭据或运行缓存。
2. 每本书单独建立 `scope.json`。正文范围必须使用唯一标题的半开区间；标题不唯一、标题缺失或正文为空时停止，不猜测范围。
3. 默认排除版权页、目录、推荐序、译者序、营销文案、扫码测试、致谢、参考书目和其他非作者正文；具体排除决定必须落入任务文档与 `excluded_sections`。若某段属于作者引用他人，应保留署名并标记 `quoted_other`，不能归为作者本人。
4. `source_sha256`、字符位置和正文快照是证据事实源。知识卡、关系和检索索引都是派生物；检索结果不能反向补充书中事实。
5. 原书路径必须由 `configs/local.json` 的 `source_books_root` 解析。工具只读访问；不得复制、移动、重写、清理或批量改名原书。
6. 页码不可靠时只记录章节、段落 ID 和字符范围，不填造页码。正文中没有的跨书结论只能作为系统推断，不能写成作者原文。

## 逐书验收门禁

每本书必须按以下顺序产出证据；任一门禁失败，只重试受影响任务，不覆盖成功输出和已完成书籍。

### 门禁 1：来源与范围

- `inventory_books.py` 能发现计划中的相对路径。
- 读取到的源文件指纹写入任务状态；源文件变化后旧任务只能重新准备。
- `normalize_markdown` 通过标题唯一性、范围顺序、非空正文和字符位置检查。
- 记录纳入章节数、段落数、排除标题及排除理由。

### 门禁 2：完整阅读覆盖

- 每个有正文的纳入 `section_id` 都出现在蒸馏输出的 `sections_reviewed`。
- 输出同时覆盖框架、原则、案例、反例和术语视角；书中没有对应类型时记录“无可靠内容”，不能凑卡。
- 失败或未完成的 unit 保留状态，不得用部分输出标为完成。

### 门禁 3：证据与结构

- 每张卡片至少有一条同书证据；案例、条件和反例必须能回读到对应正文。
- 每条证据的短引、源指纹和字符区间必须通过结构验证。
- 关系端点必须存在，关系方向、依据类别和证据 ID 必须有效。
- `complete` 必须从该书自己的任务正文重新装配，并拒绝外部候选或修改过的输出。

### 门禁 4：语义抽样

- 每本书跨章节抽样至少 12 张卡，尽量覆盖主张、方法、定义、案例/反例等实际存在的类型。
- 抽样回读原文，检查作者归属、条件边界、反例、第三方引语和“作者观点/系统推导”边界。
- 记录至少 5 道书内检索题和 1 道明确超范围题；固定题目后再比较关键词、向量和混合召回。
- 这一门禁的结果必须准确标为 Agent 自检与根 Agent 抽样复核，不能写成独立人工逐卡审计。

### 门禁 5：单书发布候选

只有门禁 1–4 全部通过的目录才能标为 `accepted_candidate`，进入十书合并。未通过的书仍可保存在独立任务目录，但不得进入正式 `CURRENT`。

## 多书候选合并设计

新增一个纯文件、无模型依赖的合并能力。合并器只接受已经通过 `validate_library` 的单书候选，不读取原书，也不根据相似度生成跨书关系。

建议接口：

```python
def merge_libraries(
    candidates: list[str | Path],
    destination: str | Path,
    library_id: str,
    release_status: str = "evaluation_candidate",
) -> dict:
    """合并已验证的单书候选；候选路径、目标路径、库标识和发布状态由调用方提供。"""
```

合并规则：

1. 目标目录必须不存在；先在同一父目录创建临时目录，完成验证后原子替换，失败时删除临时目录并保留所有输入候选。
2. 每个输入候选先独立 `validate_library`。缺 `manifest.json`、缺记录、来源损坏或状态不合格时停止。
3. `book_id`、知识卡 ID、证据 ID 和关系 ID 在全体候选中必须唯一；重复 ID 直接报错，不静默改名。
4. 复制卡片、关系和证据汇编到新的多书目录。证据汇编路径按输入书库和书籍 ID 隔离；若复制后文件路径变化，重算汇编文件指纹和证据的 `source_sha256`，但保留 `origin.source_sha256` 对原书的指纹映射。
5. 合并后的 `manifest.books` 是各候选书籍清单的稳定拼接；`library_id` 标记为多书候选，`release_status` 在全部门禁通过前为 `evaluation_candidate`。
6. 第一阶段不自动产生跨书关系，不把相似主题合并成一个作者观点。关系仅保留各书候选中的有向边；跨书综合留到单独验收阶段。
7. 合并完成后再次运行 `validate_library`，并验证 `Library.list_books()` 返回 11 本书、每本卡片和证据仍能按 ID 回读。

## 合并后验收与发布

合并候选必须额外通过：

- 十一本书的清单、来源指纹和状态无重复、无缺失。
- 全量结构验证和文件指纹验证通过。
- 每本书至少保留一组固定检索题；跨书问题只用于观察召回，不得据此自动生成跨作者结论。
- 对主题重合处抽样检查，例如财富/投资、决策/思维模型、创业/定位，确认来源书籍、作者归属和条件边界没有被合并器抹平。
- 当前《纳瓦尔宝典》的既有知识版本与回归题结果保持不变；新书失败时旧库仍可查询。

正式发布仍调用现有原子 `publish_library`。发布前必须显式确认候选目录与目标库根目录；失败时保留原 `CURRENT`。发布后旧版本继续保留在 `versions/`，可通过恢复旧 `CURRENT` 的既有发布流程回退。实际发布不是本设计自动执行项。

## 六项架构影响检查

1. **职责归属**：十书登记与批次状态属于 `distillation`；候选结构和来源合并属于 `distillation`/`knowledge` 的文件适配边界；知识验证和版本发布继续复用 `knowledge.library`；CLI 只负责参数和结果，不承载蒸馏规则。
2. **事实源与派生物**：外部原书与规范化正文是事实源；单书卡片、关系、证据汇编、多书索引和答案包都是派生物。合并器只能组合已经存在的派生物，不创造书中事实。
3. **依赖方向**：计划清单 → 单书任务 → 单书候选 → 多书候选 → 检索/调用。领域规则不依赖浏览器、HTML、Agent 会话或付费 API。
4. **接口与测试接缝**：合并器用目录和 JSON 作为输入输出；通过重复 ID、损坏证据、来源路径越界、旧版本指纹和失败回退测试隔离风险。语义抽样仍是单独验收，不由结构验证替代。
5. **变化隔离**：每本书保留独立 `book_id`、任务、证据和候选目录；新增一本书不改已有卡片 ID，不修改通用 Skill 主流程；跨书关系另行设计。
6. **迁移与回退**：不迁移原书、不改既有版本；多书候选以新目录生成，发布使用新版本号和原子 `CURRENT`；合并失败或新版本不合格时保留旧版本与各单书候选。

## 非目标与后续边界

- 本阶段不实现自动模型调度、预算统计、并发队列或自动失败重试。
- 本阶段不做作者团人格合成、不把多本书生成一个新作者、不自动建立跨书知识边。
- 本阶段不处理没有标题结构的候选书；`福格行为模型`、`金钱心理学`、`影响力`需要先单独完成结构化预处理和范围确认。
- 本阶段不将原书全文复制到交付包；证据汇编只保存被卡片引用的离散短引，并保留原书来源指纹和位置。
- 本阶段不发布、不上传、不安装到用户全局 Agent 目录；正式发布仍需在候选验收后获得明确指令。

## 预期交付物

实施完成后应有：

- 可提交的十书计划清单，不含绝对路径、凭据和运行缓存。
- 每本书独立且可重跑的 scope、任务状态、输出指纹和验收记录。
- 支持多书候选合并、重复 ID 拒绝、来源隔离和失败回退的纯领域实现与测试。
- 十书合并候选的结构验证、检索复测和语义抽样记录。
- 更新后的蒸馏工作流和架构文档，明确“已完成十书候选”“已正式发布”和“仍在蒸馏”三种状态。
