# 答案包表达规则

`AnswerPacket` 是书库驱动回答的事实边界。它不是最终文案，也不是模型隐藏思维链；它记录可验证的知识调用、显式判断和来源。

## 默认结构

### 1. 结论预览

用一小段话直接回应用户当前最需要判断的事项。注明结论依赖的关键用户事实和主要不确定性，不在这里堆引用。

### 2. 本次调用账单

说明检索范围、实际搜索书目、检索角度、是否发生关键词降级、候选数量和采用数量。展示采用卡片；是否逐项展示淘汰卡片遵循策略，但不能从底层账单删除淘汰记录。

不要写“调用了整个知识库”来制造效果。只能说全部可用书目获得了检索机会，或明确说明实际过滤范围。

### 3. 知识见证卡

每张采用卡用相同的小结构表达：

1. **来源**：书名、作者、章节、卡片 ID；
2. **知识主张**：书中观点的准确概括；
3. **原理**：为什么成立、通过什么机制影响结果；
4. **条件和边界**：何时适用、何时不能机械使用；
5. **与你的对应**：映射到用户哪项明确事实或标注假设；
6. **对判断的影响**：它支持、挑战、限制或改变了什么；
7. **证据**：证据 ID；必要时提供经验证的短引。

`principle_gap=true` 时直说当前卡片没有充分保存原理，不用常识补写成作者观点。`source_gap=true` 时不把知识署名为作者原创主张。

### 4. 交叉验证

分别表达一致、冲突、限制、替代路线和证据缺口。跨书一致不等于事实证明；同书近义卡不算两个独立来源；冲突按前提和适用条件分析，不按票数裁决。

没有真实反方时写“当前书库未检索到足够反方证据”，不要编造一位反方专家。

### 5. 综合裁决

说明哪些用户事实最关键、哪些知识真正改变结论、为什么暂时采用这一方向、还有哪些不确定性。只表达答案包中的显式依据，不补写无法验证的心理过程。

### 6. 行动方案

每一步包含：动作、依据卡片、完成标准、验证信号、停止条件或改向条件。将知识迁移写成系统建议，例如“据此可尝试”，不伪装为作者针对用户给出的原话。

### 7. 来源

列出实际使用的书名、作者、章节、卡片 ID 和证据 ID。短引以答案包中已验证内容为准；不输出长篇书摘，不提供未可靠映射的页码。

## 三种深度

- `quick`：压缩调用账单和见证卡，但至少保留来源、原理、边界和本次映射。
- `standard`：默认完整展示采用知识、主要限制、裁决和行动。
- `deep`：展开支持、挑战、边界、替代和证据审计；存在真实限制候选时必须处理。

篇幅由知识差异决定，不按卡片数量制造获得感。相同知识合并表达，但保留各自来源。

## 证据不足与一般建议

书库未覆盖时先说明缺口。可以另外提供一般建议，但使用“以下不是本次书库证据所得”等明确分隔，不能把模型记忆生成的内容写入调用账单、知识见证卡或来源列表。
