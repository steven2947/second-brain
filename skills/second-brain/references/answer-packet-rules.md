# 答案包表达规则

`AnswerPacket` 是书库驱动回答的事实边界。它不是最终文案，也不是模型隐藏思维链；它记录可验证的“问题重构—来源—原理—用户映射—知识关系—系统综合—主持裁决—继续路径”。

## v3采用边界：本次主张与原卡分开

新回答以v3见证卡的 `adopted_claim` 为本次采用内容，只用选定 `evidence_ids` 支持它；`excluded_scope` 明确哪些原卡内容没有被本次采用。原卡完整保留在会话与书库中，`original_card_ref` 只用于审计，不能据此把未采用的步骤、阈值或保证补回正文、圆桌、行动和来源。v3不自动复制原卡 `claim/reasoning/conditions/boundaries`，不要为兼容旧模板自行恢复。

`source_claim_type` 说明该采用主张的归属，系统推论、第三方转述和未知归属不能冒充作者原创。书籍署名与被引用观点的原创者分别说明；作者字段有值不等于已经核对全部合著者。条件、边界仍应充分阐释，以Agent明确判断的假设、不适用条件和误用风险为依据，不能因为隔离原卡字段就省略限制。

旧v1/v2保留历史兼容，但不具备本版的局部采用隔离，不作为新回答的静默回退。新主张的自然语言忠实度仍须读原文判断：选到了正确证据ID，不等于说的每句话都获证据支持。原理讲解、类比与系统新方案不受篇幅限制，仍须区分归属与待验证内容。

## 默认结构：三层渐进展示

第一层必须独立可用，让只想解决问题的用户无需阅读底层结构；第二、三层保留完整知识推演，让希望学习过程的用户可以继续向下阅读。分层只改变表达顺序，不得删减答案包里的采用依据、反方、边界、改判条件或来源。

### 第一层：当前该怎么做

开头直接交付足以帮助用户作决定的建议：说明当前判断、为什么优先这样做、具体怎么开始，以及关键取舍或什么情况会换路线。篇幅和建议数量由问题决定，不限一小段或三条。用户读到书籍详解之前，就应获得可用的解法；不能只给概念重构，把具体建议全部推到文末。不要在这里堆调用统计、卡片 ID 或长引用。

建议的深度来自判断的展开：目标是否明确、还有哪些值得比较的选择、建议牺牲了什么、最强反证是否改变路线。按本题需要自然展开，不把这些检查写成固定菜单。允许 AI 提出共用资源、改变顺序、保留选择权等新方案，但要说明适用前提；不能把“最快反馈”“最小行动”当成所有问题的最高目标。实验时长、样本数和阈值若是系统拟定，要交代用途和局限，不能伪装成书中定律或普遍成功标准。

### 第二层：这个结论用了哪些知识

先按本题实际结构把知识组织成知识组，再展示组内实际采用的知识见证卡。知识组说明“这组知识负责解决什么问题、书与书如何连接、还留下什么问题”；分组和卡片数量不固定。卡片标题统一为“《书名》｜作者｜知识名称”。每张卡必须让用户理解知识为什么成立、如何作用于本题，但不套固定原理模板：可根据知识本身使用因果机制、前提推导、例子、类比、反例或权衡分析，哪种更清楚就采用哪种。

每张卡至少让用户辨认出：

1. **来源**：书名、作者和知识名称；章节、卡片 ID 可放在第三层来源账本；
2. **知识主张**：书中观点的准确概括；
3. **原理解释**：为什么成立、如何影响结果；表达形式由知识性质决定；
4. **条件和边界**：何时适用、何时不能机械使用；
5. **与你的对应**：映射到用户哪项明确事实或标注假设；
6. **对判断的影响**：它支持、挑战、限制或改变了什么。

允许基于卡片和证据进一步提取、综合或延伸解释。书中直接保存的内容写成“书中主张”；系统为了帮助理解而作的推演写成“据此可以理解为”或“系统延伸”，不得把延伸内容署名给作者或伪装成原话。

### 系统综合与认知增量

在知识组之间出现可解释的新连接时，可以自由形成跨书综合、类比、待验证假设或用户未提出的新选项。说明它依据哪些卡片、为什么能推出、当前信心和还需要什么现实信号验证。系统综合不进入作者原话或书中主张；没有可靠增量时不强行制造“第三种方案”。

### 第三层：完整推演与来源账本

第三层按“独立立场—交叉质询—主持裁决”展示知识议事过程，再给出调用账单、可迁移方法和完整来源。这里可以出现检索数量、卡片 ID、证据 ID 和经验证短引。角色的立场摘要不能替代交叉质询；要让用户看见某个质疑改变、限制或保留了哪条建议，以及原因。无需为了形式制造冲突。

#### 本次调用账单

说明检索范围、实际搜索书目、检索角度、是否发生关键词降级、候选数量和采用数量。展示采用卡片；是否逐项展示淘汰卡片遵循策略，但不能从底层账单删除淘汰记录。

不要写“调用了整个知识库”来制造效果。只能说全部可用书目获得了检索机会，或明确说明实际过滤范围。

`principle_gap=true` 时直说当前卡片没有充分保存原理，不用常识补写成作者观点。`source_gap=true` 时不把知识署名为作者原创主张。

#### 第一幕：独立立场

先让每个关键席位独立表达，不预先看主持人的结论。至少展示：席位作用、书名与作者、主张、依据和它单独会作出的判断。角色代表知识在本题中的功能，不假装作者本人参加了对话。

#### 第二幕：交叉质询

围绕真正会改变结论的争议，展示“一方主张—另一方质疑—双方依赖的不同前提—冲突如何处理”。用支持、反对、矛盾、削弱前提、互补和依赖关系表达知识如何组成判断。跨书一致不等于事实证明；同书近义卡不算两个独立来源；冲突按前提和适用条件分析，不按票数裁决。

没有真实反方或替代路线时明确展示 `gap`，不要编造一位反方专家。

#### 第三幕：主持裁决

说明当前裁决、哪一方在什么条件下胜出、哪些用户事实最关键、哪些知识真正改变结论、尚未解决的分歧、信心等级和哪些新信息会使结论改判。只表达答案包中的显式依据，不补写无法验证的心理过程。

#### 行动方案

每一步包含：动作、依据卡片、完成标准、验证信号、停止条件或改向条件。将知识迁移写成系统建议，例如“据此可尝试”，不伪装为作者针对用户给出的原话。

#### 来源

列出实际使用的书名、作者、章节、卡片 ID 和证据 ID。Markdown 输出可使用 `<details>` 折叠完整来源和淘汰记录，让主文保持可读；底层记录不得因此被删除。短引以答案包中已验证内容为准；不输出长篇书摘，不提供未可靠映射的页码。

#### 用户学会的方法

用自然语言解释本次可以迁移到其他问题的方法，包括什么时候用、怎么用和什么时候停止。这一节不得只换句话重复当前结论。

#### 继续探索

同一问题已用尽主动澄清上限时（新档案最多5轮，历史无显式上限的档案最多3轮），继续方向优先是展开知识、挑战结论或推进现有方案，不能以“继续诊断”为名强制再补背景。用户主动提供新信息或选择深入学习时自然承接；说明新事实改变了哪项判断，不重复整份答案。该上限约束补齐背景的主动问诊，不限制用户继续交流。

根据本轮真实分歧、未知、证据薄弱处和用户可能的下一目标，生成一组有内容的继续路径。可以继续补充事实并诊断、展开某个知识组、围绕缺口继续检索书库、寻找反例挑战当前结论，或把裁决转成执行材料。路径数量与类型由本题决定；每条说明继续后会做什么、用户会得到什么，避免空泛地问“还需要什么帮助”。

在这些路径中推荐当前最有信息价值或最能推进用户目标的一条，并生成一条无需用户再次组织语言、可以直接发送给 AI 的指令。该指令必须出现在全文最后一行，固定使用“继续和 AI 聊：……”作为开头；来源、证据缺口和免责声明都放在它之前，指令之后不再追加内容。

## 三种深度

- `quick`：压缩调用账单和见证卡，但至少保留来源、原理、边界和本次映射。
- `standard`：默认完整展示采用知识、主要限制、裁决和行动。
- `deep`：展开支持、挑战、边界、替代和证据审计；存在真实限制候选时必须处理。

篇幅由知识差异决定，不按卡片数量制造获得感。相同知识合并表达，但保留各自来源。以上结构约束事实边界，不规定固定文案、固定专家数或固定分析框架；AI 可以根据问题自由决定如何讲清楚。

## 证据不足与一般建议

书库未覆盖时先说明缺口。可以另外提供一般建议，但使用“以下不是本次书库证据所得”等明确分隔，不能把模型记忆生成的内容写入调用账单、知识见证卡或来源列表。

## 出稿后复核

最终文案与答案包分别生成时，必须再次检查：引用书目是否实际入席；重要建议是否与条件裁决一致；知识组、关键质询、改判条件和有用的继续路径是否在表达中丢失。对照用户认可的样例检查这些功能，不复制样例的标题、字数和卡片数量。机器只核验来源映射等可确定事项；建议是否有用、原理是否讲清楚和质疑是否改变判断须做语义审阅。Agent 自审不能称为独立人工验收，文件含有 PASS 字样也不是通过证据。
